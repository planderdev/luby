1. https://luby.im/login 에서 본인 운영자 이메일로 로그인 → **설정 → 비밀번호 변경**으로 개인 비밀번호 설정(공통 초기 비밀번호는 즉시 교체)

3. **설정 → 프로필 사진**(선택) — 크리에이터·광고주가 보는 알림 발신자는 시스템이므로 필수 아님
4. 모바일: luby.im 접속 → "홈 화면에 추가"(PWA) → 앱처럼 알림·검수 처리 가능

## 2. 회원 관리 — `/dashboard/operator/users`
- 상단 **검색**(이름·이메일·회사명·사업자번호) + **운영 태그 필터**(사용 중인 태그 칩) + 탭 **승인 대기 / 전체 / 광고주 / 대행사 / 인플루언서**(각 인원 수). 행에 태그 칩 표시
- 이름 또는 "상세 →" 클릭 → **회원 상세 페이지**: 역할별 정보(사업자 정보·플랜 / 지역·소개·분야·채널·포인트), 캠페인 또는 응모·출금 이력, 추천인, 이 회원에 대한 운영 기록, 최근 알림, 승인/해제 버튼. 광고주면 "대신 만들기"·공개 프로필, 크리에이터면 포트폴리오·공개 프로필 링크
- 상세 페이지의 **운영 태그**(VIP·주의·파트너 등, 회원에게 비공개, 헤더에 표시)와 **운영 메모**(상담 이력, 상단 고정 가능, 운영자끼리 공유·회원 비공개)로 인수인계와 응대 맥락을 남기세요. 태그 변경은 운영 기록에 남습니다
- 행 정보: 광고주 → 회사명·사업자번호·**대행사 배지**·담당자 / 크리에이터 → 지역·채널 수·총 팔로워·소개 / 추천인 유무
- **승인**: 채널 URL이 실제 프로필인지(종류와 도메인이 맞는지), 소개·전문 분야가 있는지 확인 → 승인 버튼. 승인 대기가 많으면 **일괄 승인** 사용. 승인 즉시 크리에이터에게 "계정 승인" 알림·이메일
- 광고주는 가입 즉시 활동 가능(자동 승인). 문제 계정은 승인 해제로 활동 중지(캠페인 생성·응모 불가)
- **회원 추가(초대)**: 회원 관리 상단 **회원 추가** → `광고주(브랜드·자영업) / 대행사·실행사 / 크리에이터` 선택 → 이메일·이름(+회사명·사업자번호 또는 활동 지역) → **계정 전달 방식** 선택: ① **초대 메일**(비밀번호 설정 링크, Luby 템플릿) ② **임시 비밀번호 생성**(랜덤 비밀번호를 화면에서 복사해 직접 전달) ③ **비밀번호 직접 지정**(운영자가 정한 비밀번호로 즉시 생성, 8자 이상 영문+숫자) — ②③은 화면을 닫으면 비밀번호를 다시 볼 수 없으니 바로 전달하고 첫 로그인 후 변경을 안내. 운영자가 추가한 크리에이터는 바로 승인 상태. 운영 기록에 남음
- **엑셀로 내려받기**: 회원 관리 상단 버튼 → 현재 탭(전체/광고주/대행사/인플루언서) 기준 회원 CSV(엑셀 호환: 역할·연락처·승인·회사/사업자/대표자/주소/세금계산서 이메일·플랜·지역·채널·팔로워·분야·포인트·공개프로필·태그)
- **엑셀로 등록하기**: ① "템플릿 내려받기"로 양식 받기(역할·이메일·이름·연락처·회사명·사업자등록번호·활동지역·대표채널·채널URL·전문분야(;구분)·비밀번호) ② 채워서 업로드(CSV/XLSX, 300명까지) ③ **검증 미리보기**에서 오류 행 확인(이메일 형식·중복·기가입·사업자번호·지역/채널/분야 이름 인식) ④ 비밀번호 열이 빈 행의 처리 방식(초대 메일 / 임시 비밀번호) 선택 → **등록 실행** ⑤ **결과 CSV 내려받기** — 임시·지정 비밀번호는 이 파일에만 남으니 즉시 전달
- 운영자 계정은 셀프 가입으로 만들 수 없음(권한 상승 차단) — 추가 운영자는 개발팀이 생성

## 2-1. 캠페인 풀 — `/dashboard/campaigns` (운영 메뉴 "캠페인 풀")
- 플랫폼의 **모든 캠페인**(초안·검수중·모집중·마감·완료·취소) 목록. 상단 상태 칩에 건수, 업종·지역·검색·정렬 필터, 카드에 상호 + 광고주 회사명(대행사 표시)과 응모 집계 칩
- 카드 클릭 → 캠페인 상세(운영자 뷰: AI 사전 점검 결과·강제 매칭 패널 포함)

## 3. 캠페인 검수 — `/dashboard/operator/campaigns`
1. 검수 대기 목록 각 행의 **AI 사전 점검** 클릭(Opus 5, 10~20초) → `이상 없음 / 수정 권장 / 승인 보류 권장` 배지 + 이슈 목록(심각도·문제 문구 인용·광고주에게 보낼 수정 제안) + 요약. 결과는 저장되어 다시 열어도 유지, "다시"로 재점검
2. **상세보기**로 미션·제공 내역·포인트·일정·채널 확인
3. **승인** → `모집중`(광고주 알림·이메일) / **반려** → 광고주에게 반려 알림(수정 후 재요청 가능). 반려 사유는 AI 제안 문구를 참고해 채팅/메일로 전달

**검수 체크포인트**
- 경제적 대가 표기(#광고 #협찬) 미션 포함 여부 ← 가장 흔한 반려 사유
- 의료·효능 단정/과장, 확정적 수익·효과 보장, 최저가 보장 등 입증 불가 표현
- 크리에이터에게 부당한 요구(주민번호·계좌 사전 요구, 저작권 전부 양도, 부정 후기 삭제 조건)
- 미션 분량 대비 포인트·제공 내역 균형, 모집 인원·기간의 현실성, 금지 업종
- 상시 모집(always_open) 캠페인은 자동 마감되지 않음 — 의도 확인

## 3-1. 광고주 대신 캠페인 만들기 — 캠페인 검수 화면 우상단 버튼
매니지드 운영(대행·파일럿)용. `운영 → 캠페인 검수 → 광고주 대신 캠페인 만들기`
1. 회사·상호명으로 광고주 검색 → 선택 (대행사 배지 표시)
2. 일반 빌더와 동일하게 작성(AI 전부 맡기기 가능). 상단에 "○○ 광고주 명의로 작성 중" 배지
3. **검수 요청** = 운영자가 검수자이므로 **즉시 모집중**으로 시작(초안 저장도 가능). 플랜 제한(FREE 1건)은 운영자 대행에 적용되지 않음
4. 광고주에게 "운영자가 캠페인을 대신 등록했어요" 알림 발송 → 이어서 필요하면 **강제 매칭**(아래)으로 크리에이터 배정

## 4. 크리에이터 강제 매칭(배정) — 캠페인 상세 하단 "운영자 강제 매칭"
응모가 없거나 특정 크리에이터를 직접 붙여야 할 때(대행사 운영 지원·파일럿 캠페인 등) 사용합니다.
1. 운영자로 캠페인 상세(`/dashboard/campaigns/[id]`) 진입 → 하단 **운영자 강제 매칭** 패널 (검수중·모집중·마감 캠페인에서만 활성)
2. 이름·이메일·소개로 **검색** → 체크박스로 여러 명 선택 (이미 `selected/completed`인 사람은 비활성 표시)
3. 배정 메모(선택, 응모 메시지로 기록) → **N명 배정**
4. 결과: 응모가 **선정(selected)** 상태로 생성(대기·미선정·취소 응모는 선정으로 전환), 크리에이터에게 "체험단에 배정되었어요", 광고주에게 "운영자가 N명을 배정했어요" 알림. 같은 사람 재배정은 자동 건너뜀
5. 이후 채팅·콘텐츠 제출·광고주 검수·포인트 지급은 일반 흐름과 동일

> 승인되지 않은 크리에이터, 운영자 외 계정의 호출은 DB에서 거부됩니다. 배정은 광고주에게 통보되므로 사전 협의 후 사용하세요.

## 5. 정산 관리 — `/dashboard/operator/withdrawals`
- 출금 신청(신청 시점에 포인트가 이미 차감됨) 목록: 금액·은행·계좌·예금주·크리에이터·신청일
- 계좌 확인·이체 후 **지급 완료** / 문제 시 **반려**(사유 입력 → 포인트 자동 환불 + 크리에이터 알림)
- **정산 CSV**(기간 선택) → 이체 작업·회계 대사용 (UTF-8, 엑셀 호환)
- 규칙: 최소 출금 10,000P, 1P=1원. 크리에이터 포인트 출처는 콘텐츠 승인 적립·추천 보상(500P)이며 크리에이터 화면 "포인트 내역"에서 추적 가능

## 6. 결제 내역 — `/dashboard/operator/payments`
- 토스페이먼츠 결제 기록(주문·금액·상태·플랜·광고주·결제키). **결제 CSV**(기간, 대표자·주소·세금계산서 이메일 포함)로 매출 대사
- **세금계산서**: 광고주가 결제 내역에서 "세금계산서 요청"을 누르면 운영자 알림 + 목록 상단 "요청 N건 대기". 홈택스(또는 향후 팝빌 API)에서 발행한 뒤 해당 결제의 **발행 완료 처리**(메모에 승인번호) → 광고주에게 "발행되었어요" 알림, 운영 기록에 남음. 카드 결제는 매출전표가 적격증빙이라 요청 건만 처리하면 됩니다
- 테스트 계정(agency·advertiser@ruby-ai.kr 등)의 BUSINESS는 결제 없이 부여된 데모 구독

- 재무: **추천 유입 누계 · 누적 결제 매출 · 누적 포인트 지급 · 정산 대기 금액**
- **8주 추이** 5차트: 신규 가입 / 캠페인 승인·응모 / 콘텐츠 승인·포인트 지급 / 결제 매출 / 추천 유입 가입

## 7-1. 운영 기록(감사 로그) — `/dashboard/operator/audit`
- 운영자가 한 **회원 승인/해제·역할 변경 · 캠페인 승인/반려/취소 · 대행 등록 · 강제 매칭 · 정산 지급/반려**가 자동으로 기록됩니다(누가·언제·무엇을·비고)
- 작업 종류·운영자별 필터. 운영자만 열람, 기록은 삭제되지 않습니다 — 책임 추적과 인수인계에 사용

| 리마인더 8규칙 | 매일 09:30 | 첫 캠페인·임시저장·선정 지연·제출 독려·검수 지연·프로필 완성·마감 임박·운영 다이제스트 |

| 알림 → 이메일 | 즉시 | 수신 설정·수신 거부 존중, `@ruby-ai.kr`·`@luby.im`은 발송 제외 |

## 9. 계정·시스템 운영 (개발팀 협업 영역)
- **이메일**: 인증 메일 = Supabase SMTP(Resend, notify@luby.im, 브랜드 템플릿 5종) / 알림 메일 = 앱 → Resend. 반송·평판은 Resend 대시보드
- **소셜 로그인(Google·Kakao)**: Supabase Providers 설정 + Vercel `NEXT_PUBLIC_AUTH_PROVIDERS=google,kakao` 로 활성화 → 소셜 가입자는 온보딩에서 역할 확정
- **토스 라이브 전환**: Vercel `NEXT_PUBLIC_TOSS_CLIENT_KEY`/`TOSS_SECRET_KEY` 교체 → Redeploy → 소액 결제 실테스트
- **공개 페이지**: 캠페인 `/c/[id]`, 크리에이터 `/p/[id]`(옵트인) — KR/EN/CN, 사이트맵 자동
- 테스트 계정·비밀번호는 별도 보관 파일 참조(채팅·문서에 기재 금지). 데모 계정은 `@ruby-ai.kr` 도메인
